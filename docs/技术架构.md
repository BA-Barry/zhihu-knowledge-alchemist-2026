# 技术架构

```text
用户输入问题
    |
知乎官方搜索 API
    |
来源标准化 + SQLite 配额缓存
    |
知乎直答生成结构化 JSON
    |
观点矩阵 / 知识简报 / 学习卡片 / 创新路线
    |
网页核查来源 + Markdown 导出
```

## 平台边界

知乎开放平台是唯一线上内容来源，匿名 fixture 只用于无密钥演示。项目不调用其他协作平台的账号、文档、数据表、CLI 或 API。

## 组件

- `runtime/zhihu_knowledge.py`：HTTP 接口、官方 API 客户端、缓存、SQLite、导出和静态服务；
- `runtime/web/`：输入、加载、错误、成果与来源核查界面；
- `skills/`：12 个自定义知识炼金 Skill；
- `.codex/skills/zhihu-hackathon/`：原样的官方黑客松初始化 Skill；
- `.codex/skills/zhihu/`：原样的官方 CLI Skill 0.2.1；
- `demo/`：完全虚构的匿名演示；
- `tests/`：运行时、缓存、结构化成果和 Web API 自动测试；
- `Dockerfile`：公网容器部署入口。

## 数据与密钥

Access Secret 只从服务端环境变量读取，不进入请求体、浏览器、SQLite 或导出文件。项目数据默认保存在当前系统账号的 `.zhihu-knowledge` 目录。公网部署应使用平台 Secret 功能和持久化数据卷。外部调用在进程内串行执行，缓存优先，并用本地日软限额为现场演示保留官方配额。

## AI 分工

知乎搜索负责召回真实讨论及社区信号。知乎直答把本次召回内容转成约定 JSON。12 个 Codex Skill 负责完整研究模式的路由、概念图、外部证据、复核、图谱和发布准备。匿名模式只展示产品形态，不冒充真实调用。
